## 1. Decomposition

**Sound and well-bounded, with two holes.**

- The required core (#524, #525, #531) is filed, open, native-child, and each carries `serves_capstones: [502]`. The demand-gated trio (#526, #528, #530) is filed, open, and correctly *excluded* from `requires_features` — #530's own machine block restates the gate accurately, and the split matches the project's precedent (#212, #80, ARCHITECTURE.md i18n refusal) that #502 §2 cites.
- Ownership boundaries are unusually clean: verdict content stays with CAP-06 (#300/#369/#466); the rubric stays with #757; the seeded contract violation is owned once (#524 AC-2) and consumed by #531/#724 without duplication; #531 explicitly disowns cross-writer byte comparison and any submission corpus. No double-ownership found.
- **Hole 1 — the receipt has no owner.** The capstone's title, abstract, Intended Audience ("re-computable by anyone with the submission… a durable answer to 'why did I get this score'"), §1 step 2, and AC-1 all promise a per-run grading **receipt** carrying `(jls_version, lab_spec_sha256, submission_sha256, verdict_digest_sha256)`. Grep across every FEAT and TASK in the tree: **zero occurrences** of "receipt", `lab_spec_sha256`, or `submission_sha256` outside #531's claim that it "discharges CAP-21 AC-1's tuple as a build-time golden diff." A golden diff over one fixture submission proves writer determinism; it does not emit a hash-bearing artifact over an *arbitrary* student submission that a TA can re-compute in a regrade dispute. Either the children's rewrite deliberately reduced "receipt" to "deterministic, contract-versioned verdict artifact" (then #502's title/abstract/AC-1 must be rewritten to stop promising more), or the receipt is still intended (then it is a missing task — nothing in #524's frozen artifact, #466's `VerdictSet`, or #525's renderer computes a submission hash). An implementer reading this tree cannot tell which. This ambiguity alone justifies not-ready.
- **Hole 2 — PF-7 (resource envelope) is still unfiled.** `planned_features` acknowledges it, §5 defines the REPLAN path, and the DoD requires it "filed via REPLAN and closed as landed" — but no issue exists (searched titles and bodies; nothing). #502 §3 risk 6 says PF-7 "ships before any recipe is treated as production-ready," and the Gradescope recipe (#525) *is* required core, so PF-7 is effectively core, not optional. AC-6 (`ResourceEnvelopeTest`) currently composes from nothing. The codebase confirms the gap is real: `SECURITY.md` (lines 53–56) puts resource exhaustion from hostile circuit files in scope, and nothing in the tree bounds wall clock, heap, or output volume.
- Minor: #531's boundary notes name "TASK-C530-3 (nbgrader lane)" as not yet filed — acceptable since #530 is demand-gated, but it should be filed with #530's gate opening, not forgotten.
