## 2. Acceptance-criteria composition

**What holds.** AC-1/AC-6 compose cleanly from the filed children: #366's own criteria carry import-with-zero-errors, byte determinism across platforms, disposition totality over the registry, and the M1/M2 gate rules — jointly covering AC-1 checks 1-6 and AC-5's refuse arm; #349 carries footprint totality; #365 carries packing totality, cascade-in-the-IR (its criterion 3 states CAP-5's Decision 5 verbatim: synthetic nets are "ordinary nets... partitioned by the same shared pass... not invented inside an emitter") and partition equivalence (its criterion 4 is AC-1 check 5's substrate); #341's wired-AND/pull-up criteria carry AC-5's permit arm. **Gap A-1 — the realization-table medium is contradicted between the capstone and #349, and both texts are load-bearing.** CAP-5 §3 and Decision 7 prescribe "`src/jls/hdl/board/Boards.java` is the shape to copy for the v1 table: a small, deliberately-tiny table of Java constants (hypothesis H2 of #213)... rather than a general text-file format designed before a second consumer exists." #349's title ("extensible with a text file and no Java"), its capability item 1, its named-column `COLUMNS` header design (item 5), and its acceptance test IC-1 stage one ("add a part number to a text file on the classpath and, without rebuilding, query it") make the text-file format the feature's central falsifiable claim. These cannot both hold: an implementer following the capstone's §3 fails #349's IC-1; an implementer following #349 violates the capstone's recorded decision. This must be resolved by a `REPLAN:` on one side **before #400/#450 start**, since #400 (TASK-0085) is the first task on the demo slice.

**Gap A-2 — CAP-5 describes #365's refdes model that #365 has since replaced.** The roster and AC-3 text say #365 provides "canonical refdes assignment" / packing "in an order that is a pure function of circuit content." #365's own criterion 2 explicitly *replaced* refdes purity with a **committed, reconciled pack plan** (holes preserved on deletion, `--reannotate` to reclaim), on the argument that purity gives no promise under deletion and that `ElementId`'s replica component makes pure re-derivation unsafe under collaborative editing. AC-3 as written (identity via `tstamps`; refdes *may* change) survives the new model, and AC-1 checks 6-7 arguably get *stronger* under a committed plan — but the capstone's prose and the feature's contract should say the same thing before AC-1's checks 6-7 are written as tests against the wrong model.

**Named, acceptable at start.** AC-4 is correctly gated in the DoD on settling uniquified-vs-deduplicated hierarchy on #358/#292 before it is written as a test — an open design question, honestly flagged, not a hidden gap. AC-2's `kicad-cli` digest (Open Question 2) must exist before the opt-in lane is armed, and the "skipped is failing" rule in §3 is the right guard.

**Gap A-3 — the central premise is un-cited, by #349's own admission.** The entire reframe rests on "`pcbnew` discards any netlist component whose footprint field is empty." #349's Cost section states this "is asserted from general knowledge and needs a permalink to a KiCad source file and version tag before #400/#450 rely on it as settled fact." The capstone states it as fact three times. It is very probably true, and it is an afternoon to verify against KiCad 10.0.0 source — do that first; if it is even partially wrong (e.g., import warns rather than discards), the "one string per package opens the gate" framing weakens and the footprint column's priority argument changes.
