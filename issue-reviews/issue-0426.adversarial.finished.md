## Summary

The issue is open, well-evidenced against the current tree for its core
technical claims, and honest about several of its own risks — but it is
not currently actionable. Both real prerequisites are unlanded, one of
them is missing from the machine-readable `blocked_by` field entirely

the defining acceptance property has no filed gate and no CI test, and

## Findings, most severe first

**1. [Critical] The task cannot land under its own Definition of Done, and its dependency bookkeeping is stale/incomplete.** `blocked_by: [410]` names only #410. The prose separately states "TASK-0033 (section framing... ) is the second prerequisite and is not yet filed." That claim is false at the current tip: TASK-0033 was filed as **#444** (`TASK-0033: a saved file stops being one indivisible unit...`, state `open`, `part_of_feature: 319`) and is itself unlanded. #426 never references #444 anywhere, so a second live, unlanded blocker is invisible to anything reading the machine block. Worse, the edge isn't mirrored on the other side either: #444's own machine block reads `blocks: []` and `related: [..., 426]` — under this corpus's stated vocabulary ("`related` is defined ... as reference-only and never blocking," per #319/#299), #444 does not consider itself blocking #426 at all. That is exactly the "half-edge" defect other issues in this corpus (#319 §"Link pass") call out as something the Link phase exists to prevent, and it is present here. Recommendation: add `444` to `blocked_by` and get the mirrored `blocks` edge added on #444 before scheduling any code work; until then the Completion Criteria item "Every `blocked_by` entry ... has landed" is unsatisfiable by construction, because one real blocker isn't even listed.

**2. [High] The acceptance gate for the property that defines "done" is unfiled, and only exists as advisory prose, not as an enforced dependency.** The issue's own §11 Threats to Validity says: "TASK-0075 is not a verification step at the end; it is the definition of done and should be written before this task" — and the Abstract/§12 both state TASK-0075 "is not yet filed." Yet TASK-0075 appears nowhere in `blocked_by`. This means P1–P5 (per-simulator sequence, payload-switch totality, dupCheck/queue membership, `RegisterFile` round-trip, the field map) can all be implemented and pass while the property that actually matters — byte-identical continuation, P6/P8, the commuting square of §7.10 — has no CI-enforced regression test at all, only a manually-recorded PR artifact ("a full checkpoint-restore-continue run with byte-identical output"). That is precisely the gameable-acceptance-criteria pattern the issue itself warns against in its own H5 note ("a hand-reviewed field list decays every time an element ships"): the safeguard the issue names as the actual gate does not exist yet, so this task's local tests can go green while the headline claim silently drifts. Recommendation: file TASK-0075 and add it to `blocked_by`, not just cite it as should-come-first prose.

**3. [High] A cited normative document does not exist in this repository.** `docs/parity-contract.md` is cited in §6 Materials & Apparatus ("`docs/parity-contract.md` §4 — simulated time is a permitted divergence, which is why an input-log cursor and a retirement index ride alongside `now`") and its consequence — the input-log cursor and retirement index — is baked into §7.6's Engine Record as required fields. A repository-wide search (`find`, `grep -r`) turns up **zero** occurrences of `docs/parity-contract.md`, and `docs/` has no file resembling it (confirmed contents of `docs/` listed below). The requirement to carry an "input-log cursor" and "retirement index" in the checkpoint's engine record is therefore justified by a document that isn't in the tree — undermining a concrete field in the data contract. (Note: this is a known recurring defect across this issue corpus — the same missing citation has already been flagged in reviews of #343, #428, #458, #347, #333, #332, #359 — so it is systemic, not unique to #426, but it still fails #426's own Definition of Done bullet: "Every cited evidence document and permalink resolves on the default branch at close.") Recommendation: either commit `docs/parity-contract.md`, or drop the input-log-cursor/retirement-index requirement (or re-justify it) before this section is implemented against it.

**4. [Medium] A large, separable prerequisite is smuggled into this task's scope instead of being filed and gated.** O8 states plainly: "`RegisterFile` is the only simulating element with no behavioral golden... Writing its checkpoint path without one is writing untested code. Land the golden first." §6 lists it under "Must exist first," alongside TASK-0033/TASK-0011/TASK-0034 — but unlike those three, it carries no issue number and is not in `blocked_by`; it is instead a bullet inside this task's own §8 Method checklist ("Land RegisterFile's behavioral golden first"). Writing a driven-clock behavioral golden for a previously-EXEMPT element (confirmed: `test/jls/ElementSimulationGoldenTest.java:533-546` currently exempts `RegisterFile` with the reason "a behavioral golden with a driven clock is a follow-up") is itself nontrivial new-test-infrastructure work, and folding it into a "2 wk" task (per FEAT-035's own roster table) understates the task and creates an untracked internal dependency that the machine block doesn't expose. Recommendation: file the `RegisterFile` golden as its own task and add it to `blocked_by`, consistent with how TASK-0033/TASK-0011/TASK-0034 are already treated.

**5. [Medium] One refusal-list branch targets a feature that does not exist in the codebase, so it cannot be honestly exercised.** §7.11 requires refusing to checkpoint "a run holding an open host byte port." A repo-wide search for `host byte port` / `HostBytePort` / `hostBytePort` across `src/`, `test/`, and `docs/` returns **no matches** — the host byte port (FEAT-032 / #324, cited elsewhere in this corpus as downstream of FEAT-006) is not built yet. The Definition of Done requires the refusal list to be "implemented by name... with no silent skip" and P7 requires it to be "exercised, not merely written" (per #363 §5 criterion 3, which this task's completion criteria echo). Until the host byte port exists, that specific refusal branch is either dead code with no fixture that can trigger it, or gets quietly dropped from the "exercised" set — either way it's a refusal-list entry that can't be honestly verified at this task's scope. Recommendation: scope that refusal item out until FEAT-032 lands, or state explicitly that it is a forward-declared no-op until then.

**6. [Low] The one self-described safeguard against an incomplete field map is circular given Finding 2.** H5/P5 state the reflective sweep over `initSim`-touching fields is "the map, not the gate," precisely because "a hand-reviewed field list decays every time an element ships" — but the actual gate (TASK-0075) is unfiled. So today, P5's own honesty about its limits has no counterweight. This compounds Finding 2 rather than being a new independent defect; recorded separately because it is the concrete mechanism by which an incomplete field map would currently go undetected.
