# JLS (anadon/JLS fork of Poplawski's JLS 4.1) — baseline self-assessment

## FACTS
STACK: Java 25+ (floor follows current LTS), Swing GUI (FlatLaf light default), Maven build, historical src/ layout (not src/main/java). LICENSE: GPL-3.0-or-later. SIZE: ~129k LoC Java total (300 src files + 240 test files, measured locally at /home/user/JLS; ~82k of that is src). RELEASE HISTORY: upstream 4.1.5 (2014-03-18) → 12-year gap → 4.2.0-alpha.1 (2026-07-01) → 5.0.0/5.0.1/5.0.2/5.0.3/5.0.4 all on 2026-07-16, 5.0.5-SNAPSHOT active; commits daily through 2026-08-03 (CHANGELOG.md, git log). INSTALL PATHS: signed .msi (Authenticode via SignPath, x86_64 + Windows-on-ARM), .dmg (Apple silicon, deliberately unsigned — right-click-Open required), .deb/.rpm/AppImage (amd64+arm64), Nix flake (`nix run github:anadon/JLS`), self-contained jar (JDK 25+), headless container ghcr.io/anadon/jls (amd64/arm64/riscv64) — all with SHA256SUMS + cosign/gh-attestation provenance; jar+BOM bit-reproducible (README.md, docs/reproducibility.md). DOCS: normative docs/simulation-semantics.md (every claim code- or golden-test-anchored), docs/batch-interface.md (documented stability contract for -t grammar/watched-output/VCD profile), docs/vcd-interop.md, docs/file-format.md, docs/extension-points.md, ARCHITECTURE.md; in-app help is HTML 3.2 rendered in a Swing JEditorPane (resources/help/), 4-page in-jar Tutorial dialog with Prev/Next (src/jls/Tutorial.java, issue #73 resolved). README has zero screenshots. QUALITY GATES: warnings-as-errors, SpotBugs (High), NullAway/JSpecify (@NullMarked), sealed-hierarchy pinning tests, PIT mutation ratchet promoted to blocking (mutationThreshold 80 / testStrength 82, ~905 mutants), 6 CI workflows incl. CodeQL, Scorecard, installer-repro. COMMUNITY NUMBERS: 3 stars, 9 forks, 255 open issues (overwhelmingly maintainer-authored roadmap/spec issues), single maintainer, AI-assisted development. SOURCES: https://github.com/anadon/JLS ; https://github.com/anadon/JLS/releases ; local /home/user/JLS (README.md, CHANGELOG.md, CONTRIBUTING.md, docs/, src/jls/).

## SCORES
- onramp_install: 4 — Signed no-JDK installers on every OS plus AppImage/Nix/jar/container is best-in-desktop-class, but no zero-install web version and macOS needs the right-click-Open Gatekeeper dance (unsigned by choice), so it cedes the 5 to browser tools.
- onramp_learning: 2 — First launch is a bare empty canvas with no in-canvas guidance, README has zero screenshots, the in-jar tutorial is 4 static HTML pages behind a menu, and help is HTML 3.2 in a Swing viewer — a student's first 10 minutes are unassisted.
- tech_sim_semantics: 4 — Delay-accurate discrete-event model with a normative, code-anchored semantics spec (docs/simulation-semantics.md) pinned by golden tests is category-leading rigor, but the 2-state+HiZ value domain (no per-bit X/Z, no hazard/unknown propagation) caps it below 5.
- tech_scale_perf: 2 — An RV32I worked example proves processor-scale circuits simulate, but zero published throughput numbers exist anywhere in repo or docs — against Digital's advertised ~120 kHz processor claim JLS has no answer on record.
- tech_hierarchy_reuse: 2 — Subcircuits exist and files can be imported as elements, but there is no subcircuit parameterization (generics/width parameters), no component library ecosystem, and no cross-file library management.
- tech_testing_grading: 5 — Batch -t test vectors with a documented stability contract (docs/batch-interface.md), VCD/SVG/PNG export, deterministic exit codes, a headless multi-arch container built for autograders, and examples/autograde/autograde.py — no competitor documents grading as a contract.
- tech_hdl_interop: 3 — Structural Verilog-2005 and VHDL export plus VCD interop docs and a scripted iCEstick bitstream handoff (scripts/icestick-handoff.sh) beat most edu tools, but there is no HDL import and no first-party in-GUI FPGA flow like Logisim Evolution's board download.
- extensibility: 2 — A typed ExtensionPoint/ExtensionRegistry mechanism with 4 catalogued seams just landed (#223/#220, docs/extension-points.md), but it currently only boots compiled-in subsystems — there is no shipped third-party plugin loading, scripting, or example external component.
- code_elegance: 4 — JDK 25, JSpecify/NullAway null-safety, sealed exhaustive dispatch, records, blocking 80% mutation ratchet, reproducible builds, and normative architecture docs are exceptional; the 5,852-line SimpleEditor god class and legacy src/ layout deny the 5.
- contributor_experience: 3 — CONTRIBUTING.md is precise (regression-test-per-fix, style contract, issue-first) and issues carry file:line evidence and acceptance criteria, but there is zero demonstrated external-PR throughput, one maintainer as sole reviewer, and 255 open issues of dense self-authored spec prose that reads as a wall to newcomers.
- community_size: 1 — 3 stars, 9 forks, 1 active contributor, no known current course adoption of this fork (upstream MTU usage is historical; the bsiever fork served a WashU course) — effectively zero community.
- momentum: 4 — From a 12-year-dead codebase to five releases in July 2026, daily commits through 2026-08-03, a blocking-gate quality program and an explicit capability roadmap (docs/capability-roadmap/) — steep upward trajectory, held to 4 by single-maintainer bus factor and zero external validation.

## TOP USER COMPLAINTS
- Crashes on edge-case circuits: stateless FSM crashes the simulator (bsiever/JLS #24, open), file-open crash (#10, closed in that fork), fractional HiDPI scale factor crash (#6, closed) — stability under real student input was the dominant course-era pain (https://github.com/bsiever/JLS/issues)
- Tri-state bundles fail to connect (bsiever/JLS #19, open) — the HiZ/bundle interaction breaks exactly the feature that distinguishes the wire model
- Data-loss ergonomics: closes without prompting to save unsaved work (bsiever/JLS #3), and Save/Save-As behavior needed course-driven patching (#5, #15)
- Weak selection/editing ergonomics: no compound multi-element selection manipulation (bsiever/JLS #18) — editing anything beyond a single gate is tedious in the classic editor
- Error UX that dead-ends: the exception handler gives advice the program then refuses to follow (bsiever/JLS #9) — students hit walls with no recovery path
- Over-restrictive identifier rules: wire names reject '!' and '\\' (bsiever/JLS #4), blocking conventional active-low naming
- Export gaps drove forking at all: PNG export had to be added by a course instructor (bsiever/JLS #13) — upstream-era JLS lacked basic artifact export (now shipped in anadon fork as -i PNG/SVG/JPEG)
- Upstream abandonment itself: 4.1.5 sat untouched 2014-2026, forcing instructors like bsiever to self-patch to keep courses running — the meta-complaint behind every fork

## DEV COMMUNITY
Effectively a community of one. Upstream author David Poplawski (Michigan Tech) wrote it as a course tool and stopped at 4.1.5 in 2014. The only organic outside activity was Bill Siever's WashU course fork (bsiever/JLS), which patched crashes and added PNG export to keep a class running — course-instructor-as-reluctant-maintainer, the classic edu-tool pattern. The anadon fork is a single maintainer doing high-velocity AI-assisted development. ATTRACTS: a genuinely trivial build (JDK 25 + `mvn verify`, nothing else; headless test suite), unusually rigorous issue hygiene (file:line evidence, acceptance criteria, an ordering meta-issue), modern Java that is pleasant to write, and normative docs that make the system learnable without archaeology. REPELS: no audience (3 stars means a contribution reaches nobody), Swing carries a stigma with exactly the students who might contribute, the 5,852-line SimpleEditor concentrates dread where UI contributions would land, strict gates (mutation ratchet, warnings-as-errors, style-matching mandate) raise the entry bar, 255 open issues of dense maintainer-authored spec prose read as an internal monologue rather than an invitation, and the single maintainer is the sole reviewer — a bottleneck and a bus-factor-of-one in one. No good-first-issue on-ramp is evidenced.

## SWITCH ANALYSIS
### pull_users
PULL INVENTORY (what JLS has that rivals lack): (1) autograding as a documented stability contract — -t vectors, deterministic exit codes, watched-output format, VCD profile, headless multi-arch container — no rival documents grading semantics at all; migration cost for an instructor is writing vector files, ~hours. (2) Supply-chain-grade artifacts: signed installers, cosign/attestation, reproducible jar — uniquely relevant to institutional lab deployment. (3) A normative simulation-semantics spec with golden tests — instructors can cite what a simulation means. (4) Verilog+VHDL structural export plus VCD into GTKWave/Surfer as an on-ramp to real EDA. (5) Plain-text .jls re-save for git-diffable student submissions.
### pull_devs
The pull for developers is the codebase itself: JDK 25 with sealed types, records, JSpecify null-safety, a blocking mutation-testing ratchet, reproducible builds, and issues pre-loaded with file:line evidence and acceptance criteria — versus Logisim-Evolution's aging codebase or CircuitVerse's Rails+JS sprawl. A contributor who values engineering discipline over audience gets a cleaner home here than in any competitor. But with 3 stars there is no status payoff, so this pull only works on discipline-motivated contributors, and the single-reviewer bottleneck must not stall their first PR.
### jls_deficits
BOUNCE LIST — what makes a switcher leave in the first 10 minutes: (1) no web version — every CircuitVerse/simulator.io user bounces at 'download an installer'; (2) README with zero screenshots — the tool fails social proof before first launch; (3) first launch is an empty canvas with no in-canvas guidance, palette hint, or open-the-tutorial nudge; (4) help renders as HTML 3.2 in a Swing pane — instantly signals 1998; (5) no chronogram/timing-diagram panel — Digital/Logisim users expect waveforms in-GUI, not via VCD export to a second tool; (6) 2-state value domain — anyone teaching X/Z propagation bounces; (7) no subcircuit parameterization — Digital users with generic-width components bounce; (8) Swing-era look and a 3-star repo fail the credibility sniff test against 5k-star rivals.
### winnable_verdict
Winnable segment: course staff who autograde — instructors and TAs running batch pipelines, plus the small population of discipline-motivated Java contributors. Not winnable now: browser-first students (no web build), waveform-centric users (no chronogram), HDL-teaching courses needing X/Z. Minimum bar to clear before any user pull is realistic, in order: screenshots + animated GIF in README (days of work, blocks everything else), a first-run experience that opens the tutorial or a starter circuit instead of a blank canvas, an in-GUI chronogram panel, and one public head-to-head autograding case study proving the grading contract on a real course. Until those four land, JLS's genuine technical superiority in testing/grading and build integrity is invisible at the moment of first contact, and every switcher bounces before discovering it.
