# Issie (tomcl/issie) + DigitalJS/yosys2digitaljs (tilk/digitaljs) — two academically-authored HDL-adjacent editors. NOTE: each numeric score = the HIGHER (worst-case-threat) of the two tools; the per-tool split is spelled out in each 'why'.

## FACTS
ISSIE: F# transpiled via Fable to JS, Electron desktop app, Elmish MVU, custom F# schematic-editor library, Webpack 5, paket+npm dual package chain (https://github.com/tomcl/issie README). GPL-3.0. 88 stars, 106 forks (forks inflated by Imperial coursework teams), 3,345 commits, 44 open issues. Built and used in teaching at Imperial College London EEE/EIE; students learn F# in the 3rd-year High-Level-Programming course explicitly 'hence can maintain the app in the future' (README). Releases: annual academic-year cadence — v3.0.11 Sep 2022, v4.1.3 Sep 2023, v5.1.20 Aug 2024 (new waveform simulator), v5.3.2 Aug 2024 (large-design memory-leak fixes), v5.9.3 Mar 2025 (parameter model, breaking save format), v6.0.4 'Summer Maintenance 2026' Aug 2026 (improved parameter system, library catalog where 'library components written with parameters appear identical to built-ins') (https://github.com/tomcl/issie/releases). Install: prebuilt zips for Windows and macOS ONLY, ~200MB, unzip-and-run, SmartScreen/Gatekeeper warnings documented in README; no Linux binary; fails from networked drives without --no-sandbox (issue #125). Docs: user site https://tomcl.github.io/issie/ + user guide (apantelopoulos.github.io/IssieBlog/user-guide/) with screenshots; 16-page contributor wiki (architecture, width inference, Verilog component, Elmish patterns, macOS signing) + a dissertation as code intro (https://github.com/tomcl/issie/wiki). Features: hierarchical sheets, custom components, NEW parameter system + component libraries (v6), bus width inference with beginner-oriented error messages, cycle-based synchronous 2-state simulation (no propagation delays, no X/Z), combinational-loop detection, waveform simulator (reorderable waves, bin/hex/signed/unsigned radix, jump-to-cycle), truth-table generation (4th-year student FYP, KaTeX logic expressions), structural Verilog export ('Write design as verilog'), partial Verilog IMPORT via 'Verilog component' (own compiler, subset), memories with backup snapshots. DIGITALJS: plain JavaScript npm library (v0.14.2), BSD-2-Clause, 775 stars, 67 forks, 497 commits, 8 open issues (https://github.com/tilk/digitaljs). Author: Marek Materzok (tilk), University of Wrocław; CSERC'19 paper 'DigitalJS: a Visual Verilog Simulator for Teaching' (doi 10.1145/3375258.3375272). Deps: @joint/core (rendering), elkjs (auto-layout), 3vl (three-valued 0/1/x logic vectors), web-worker (async sim engine), wavecanvas (waveforms), jquery/jquery-ui. Simulates circuits synthesized by Yosys via companion yosys2digitaljs (60 stars, 28 forks, 165 commits, https://github.com/tilk/yosys2digitaljs); JSON circuit format with devices/connectors/subcircuits (subcircuit defs cannot nest own subcircuit definitions); rich cell library incl. FSMs, multi-port RAM with collision/transparency attributes, Intel HEX + Verilog RAM import/export, SVG export, Verilog export. Zero-install web app digitaljs_online (151 stars, Node backend running real Yosys) at https://digitaljs.tilk.eu/. Deployments: Télécom Paris self-hosted instance https://digital.r2.enst.fr/ (adapted 7-seg to their Terasic DEx FPGA boards); CircuitVerse forked yosys2digitaljs-server for its Verilog-import feature; two VS Code extensions (yuyichao.digitaljs — runs Yosys via WASM client-side; michal-markiewicz.digitaljs-vsc). Activity: maintenance-mode but alive — Feb 10 2026 'Enable simple changing of default combinational propagation time', Feb 3 2026 'Reduce dependencies', Dec 2025 jointjs-update fixes; committers tilk + drive-by contributors (mpnogaj, yuyichao, mateusz-sz).

## SCORES
- onramp_install: 5 — DigitalJS 5: zero-install web (digitaljs.tilk.eu) — paste Verilog, press synthesize; Issie 3: unzip-and-run zip for Windows/macOS only (~200MB, SmartScreen/Gatekeeper friction, no Linux binary, breaks on network drives per #125) — JLS's signed all-OS installers beat Issie but nothing desktop beats a URL.
- onramp_learning: 4 — Issie 4: purpose-built for beginners with width-inference error messages, bundled demo projects, screenshot-rich user guide and an actual course wrapped around it; DigitalJS 3: examples dropdown + paper, but docs are a JSON cell-format reference, no tutorial arc.
- tech_sim_semantics: 4 — DigitalJS 4: three-valued 0/1/x per-bit logic (3vl), event-driven engine with configurable combinational propagation time (Feb 2026), tristate/bus support — beats JLS's 2-state domain but is unit-delay, no documented hazard/stability contract; Issie 2: cycle-based synchronous 2-state, no delays, no X/Z, no glitches — only combinational-loop detection; JLS's delay-accurate discrete-event sim with documented stability contract beats both on timing rigor.
- tech_scale_perf: 3 — Issie 3: handles full student CPU designs, but needed 2024 memory-leak fixes for large designs and maintainer's own open issue #515 'Better handling of large designs' (Mar 2025) remains; DigitalJS 2: browser+elkjs auto-layout chokes on large synthesized netlists, web-worker engine mitigates; neither publishes throughput numbers (vs Digital's ~120 kHz claim).
- tech_hierarchy_reuse: 5 — Issie 5: hierarchical sheets + v6.0 parameter system + library catalog where parameterized library components 'appear identical to built-ins' — exactly the subcircuit parameterization JLS lacks; DigitalJS 3: JSON subcircuits instantiable but flat definition namespace, parameterization delegated to Verilog/Yosys.
- tech_testing_grading: 3 — DigitalJS 3: as an npm library it is headlessly scriptable (CircuitVerse drives it server-side) but ships no vectors/grading tooling; Issie 2: truth tables and waveform sim are interactive-only, no CLI, no batch mode; JLS's -t vectors + VCD + documented determinism is category-leading among all three.
- tech_hdl_interop: 5 — DigitalJS 5 (in its niche): full Verilog/SystemVerilog import through real Yosys synthesis (yosys2digitaljs), plus Verilog export, Intel HEX memory I/O, SVG export, WASM-Yosys VS Code path; Issie 4: structural Verilog export plus genuine partial Verilog IMPORT ('Verilog component', own compiler subset) — both currently ahead of JLS's export-only story until CAP-08/FEAT-020 lands; neither has a first-party FPGA flow (Télécom Paris board adaptation is third-party).
- extensibility: 4 — DigitalJS 4: documented JSON format, embeddable npm library, pluggable engines — third parties built two VS Code extensions, a hosted instance, and CircuitVerse integration without touching core; Issie 2: no plugin/scripting surface, extending means writing F#/Elmish inside an Electron monolith.
- code_elegance: 4 — DigitalJS 4: small, layered ES-module library (engine/render/convert split, 3vl abstraction) with a peer-reviewed design paper, though jQuery-UI dates it and test culture is thin; Issie 3: strongly-typed F#+Elmish is principled, but 3,345 commits of annual student churn produced the maintainer's own open issue #531 'Organise the code base', and the Fable+Electron+Webpack+paket+npm chain is heavy — JLS's mutation-testing/NullAway gates exceed both.
- contributor_experience: 3 — Issie 3: exceptional onboarding docs (16 wiki pages, dissertation, coding guidelines) but requires .NET 10 SDK + Node 22 + npm 11 + F#/Fable/Elmish/Electron — effectively only Imperial HLP graduates clear the bar, and one professor merges everything; DigitalJS 2: no CONTRIBUTING, issues open 2-4 years (#72 since 2022, #96 since 2023), single academic maintainer, though external PRs (mpnogaj) do get merged.
- community_size: 3 — DigitalJS 3: 775 stars + 151 (online) + 60 (converter), real third-party deployments (Télécom Paris, CircuitVerse, 2 VS Code extensions) but ~1.5 active devs; Issie 3: 88 stars but a guaranteed captive user base of hundreds of Imperial students annually and ~zero documented adoption anywhere else; both dwarf JLS's 3 stars in users, neither has a real dev community.
- momentum: 4 — Issie 4: unbroken annual release rhythm 2022-2026 tied to the academic year, major v6 parameter/library features Aug 2026, active maintainer triaging weekly; DigitalJS 2: maintenance mode — v0.14.x dependency bumps and rendering fixes, README TODOs (gate-level reduction, i18n) untouched for years.

## TOP USER COMPLAINTS
- ISSIE — crashes on ordinary editing: deleting a malformed default input value crashes the app (issue #588, Nov 2025); property-pane gaps like BusSelect LSB not editable (#581, filed by the maintainer himself)
- ISSIE — large designs degrade: 'significant memory leaks affecting large designs' only fixed in v5.3.2 (Aug 2024) and maintainer-filed #515 'Better handling of large designs' (Mar 2025) still open
- ISSIE — discoverability/UX friction: features need popup hints (#519), no rename keyboard shortcut (#526), duplicated components unsorted (#528) — power-user workflow polish lags the beginner polish
- ISSIE — platform friction: Windows/macOS zips only (no Linux binary), SmartScreen/Gatekeeper warnings on first launch, refuses to start from networked drives on cluster machines without --no-sandbox (#125) — painful in exactly the uni-lab setting it targets
- ISSIE — save-format breakage: v5.9.x projects 'saved in a form incompatible with lower versions' (release notes) — risky mid-course upgrades
- DIGITALJS — it is a viewer, not an editor: you cannot draw or rewire circuits, only simulate synthesized/JSON netlists; even editing a Number input doesn't retrigger logic (#106, open since Apr 2023)
- DIGITALJS — bitrot at the edges: 'Old webpack / no pre-built files in releases' (#96, open since 2023), elkjs breakage when loaded as a module (#111), gates rendering black after jointjs update (#113), layout lock/desync of inspected elements (#72, open since Feb 2022)
- DIGITALJS — maintainer bandwidth: 2-4-year-old open issues and a README TODO list untouched since ~2019 signal that integrators (Télécom Paris, CircuitVerse) must self-support

## DEV COMMUNITY
ISSIE is a walled-garden contributor machine: one emeritus professor (tomcl) plus an annual conveyor belt of Imperial 3rd-year HLP students who learn F# in the course and do team projects on the codebase (explaining 106 forks vs 88 stars — forks are coursework). Attracts: students get a real 80k-commit-history app, superb onboarding wiki, a dissertation as architecture doc, and guaranteed maintainer attention. Repels everyone else: F#+Fable+Elmish+Electron is a stack almost no outside hardware-tools contributor knows; dev setup needs .NET 10 SDK + Node 22 + forced npm 11 upgrade + paket; all merges bottleneck on one person; contributors graduate and vanish yearly, which is why the maintainer's own issues #531 'Organise the code base' and doc-tooling breakage (#532) exist. Net: high throughput, zero retention, zero external gravity. DIGITALJS is a one-academic library with an integrator halo: Marek Materzok (U. Wrocław) wrote and still merges everything; drive-by contributors (mpnogaj, yuyichao, mateusz-sz) fix deps and rendering. The BSD-2 license and clean npm-library shape attract INTEGRATORS — Télécom Paris self-hosts an FPGA-board-adapted instance, CircuitVerse forked yosys2digitaljs-server for its Verilog import, two independent VS Code extensions exist — but integrators build around the core, not in it. Attracts: embeddability, permissive license, published paper, small comprehensible codebase. Repels: no CONTRIBUTING, multi-year issue latency, jQuery-era frontend, and the author's research time is clearly elsewhere. Net: healthy downstream ecosystem, near-zero upstream velocity.

## SWITCH ANALYSIS
### pull_users
ISSIE users don't choose Issie — Imperial course staff do; the winnable slice is the long tail who find Issie on GitHub and bounce: Linux users (no Issie binary — JLS has signed installers + Nix + container on every OS), instructors needing autograding (Issie has zero CLI/batch; JLS has -t vectors, VCD, stability contract), and anyone teaching timing/glitches (Issie's cycle-based sim literally cannot show a hazard; JLS's delay-accurate sim can). Migration cost is real but tractable: Issie's project format is open JSON sheets, so an issie-to-JLS importer is feasible; without one, redrawing is the cost. DIGITALJS users are Verilog-first people who want 'paste HDL, see it run in a schematic' — they cannot be pulled until JLS's Yosys import (CAP-08/FEAT-020) ships; after that, JLS's pitch is delay-accurate simulation + VCD + grading of the synthesized netlist at desktop scale vs DigitalJS's unit-delay browser viewer that chokes on big netlists. Strategically DigitalJS is more complement than threat: yosys2digitaljs is BSD-2-licensed, so its battle-tested Yosys-cell-to-component mapping is directly reusable as the reference (or dependency) for JLS's own importer.
### pull_devs
ISSIE's contributors are F# students who disperse on graduation — there is no retained community to pull, and people who chose F# will not romance a Java/Swing codebase; the realistic 'pull' is one or two ex-Issie students per year who want mainstream-stack resume value and would be drawn by JLS's strict quality gates (mutation testing, NullAway, warnings-as-errors) versus Issie's 'Organise the code base' debt — market via a comparison page and good-first-issues. DIGITALJS has essentially no core dev community to pull (1 academic + drive-bys); its INTEGRATORS (CircuitVerse, Télécom Paris, VS Code extension authors) want an embeddable JS library, which desktop-Java JLS structurally cannot offer — do not chase them, but a JLS headless-CLI-with-JSON-output could serve the server-side graders among them (CircuitVerse's use case) better than a browser lib.
### jls_deficits
Brutal list: (1) No zero-install path — DigitalJS's URL beats every installer JLS will ever sign, and this is DigitalJS's entire moat; (2) DigitalJS's per-bit 3-valued x-propagation is semantically richer than JLS's 2-state+HiZ domain — an unknown-value story JLS currently loses; (3) DigitalJS has full Verilog IMPORT today via real Yosys, Issie has partial import via its own compiler — JLS has none until FEAT-020 ships; (4) Issie v6's parameter system + library catalog is exactly the subcircuit parameterization JLS lacks, and Issie shipped it first; (5) Issie's width inference with beginner-targeted error messages and its waveform UX (reorder, radix, jump-to-cycle) are UX innovations JLS's Swing UI does not match, and JLS has no chronogram panel at all; (6) community optics: 3 stars and no README screenshots vs 88/775 stars, a course deployment, and third-party instances — JLS looks less alive than a maintenance-mode project; (7) both competitors were born in institutions that supply users automatically; JLS has no institutional channel.
### winnable_verdict
Issie's captive Imperial base is NOT winnable (the tool is the curriculum; switching cost is a course redesign) — the winnable segment is non-Imperial instructors and Linux/self-hosted users who evaluate Issie and hit the Windows/macOS-only wall, plus any instructor needing autograding or real timing; minimum bar: README screenshots, subcircuit parameterization, a chronogram panel matching Issie's waveform UX, and ideally an Issie-JSON importer. DigitalJS's users are winnable only in the post-Yosys-import world and only the grading/desktop-scale slice; its browser-embed audience is permanently out of reach without a JLS web story — treat DigitalJS as a complement (reuse yosys2digitaljs's BSD mapping to de-risk FEAT-020) rather than a rival. Across both, the highest-leverage takeaways are ideas, not people: adopt Issie's width-inference error-message philosophy and parameter/library model, adopt DigitalJS's x-propagation semantics, and fix the JLS shop-window (screenshots, live demo GIF, comparison table) — without that, neither tool's users will ever click through long enough to discover JLS's genuinely superior simulation and grading core.
