**Gaps (in descending severity):**

1. **#554 AC-1's batch-mode flag is unowned, and its own task contradicts it.** #554 AC-1 requires "a batch-mode flag on the existing headless surface, documented under `docs/batch-interface.md`," writing the run record to a file — necessarily a `src/` change (`JLSStart` `FLAGS` table). #726 (TASK-C554-1), the task that owns the instrument, instead builds a test-tree `Simulator` subclass behind `-Pbench` and states it "adds no new production field and needs no `src/` change," explicitly citing #442 §7.5's refusal to promote a counting subclass into `src/`. #730 then presumes both exist ("#554's batch-mode flag (AC-1) writes a run record to a file; #726's harness populates it"). Either #554 AC-1 must be revised to bless the `-Pbench` harness as the instrument (and CAP PF-1's "documented CLI surface" language softened to match), or a task must own the flag. As written, #554 cannot close with its current tasks, and the capstone's "committed, documented CLI instrument" outcome hangs on the unresolved half.
2. **FEAT-C28-4 (#560) is inverted: its required core has no task; its optional scope has both tasks.** #560 declares AC-1 (harness packaged as a Nix-flake/container reproducible unit, fetch-by-hash, published third-party invitation) and AC-2 (capability-deficit table) as the *required* core at 0.5–1 mw, with the self-run head-to-head *optional* (AC-3). Its two tasks — #740 (adapters, same-machine run) and #742 (published head-to-head table with mandated loss) — are precisely the optional self-run, summing to 1–2 mw, and neither covers AC-1's packaging/invitation nor AC-2's deficit table.
3. **The shared runner / adapter-descriptor contract #740 plugs into is owned by nobody.** #740 AC-1: adapters conform to "#554's runner/adapter-descriptor contract (tool, pinned release tag, artifact URL, sha256, invocation, recommended-settings block, citation URL)" and "does not build a runner... that is #554's." #554, #726, #728, and #730 nowhere promise a multi-tool runner or adapter descriptors — #554's own boundary table says "Nothing else in the chain measures a competitor," and its suite is a JLS-only `-Pbench` harness. #740's foundational premise points at a deliverable no issue in the corpus owns.
4. **The capability-deficit table (CAP AC-5, #560 AC-2) is orphaned by triangular assignment.** #560 AC-2 places the #510 §2 table in `docs/performance.md`; #742's boundary says the table "is #555's (FEAT-C28-2) content"; #555 and its tasks (#732, #733) never mention it — #555 AC-3's trade table is a different artifact (timing-model costs/benefits, not the hierarchy/chronogram/FPGA/value-domain/on-ramp deficit table). Every child can pass while CAP AC-5's table clause fails.
5. **#557 AC-1's `PublishedNumberProvenanceTest` has no task**, and #738's grounding says so explicitly ("No issue currently owns building it — flagged here, not resolved here"). #557's decomposition section says the feature is "implemented by two already-filed tasks," neither of which builds AC-1.
