**2. [High] The issue is packaged as a ready-to-execute task despite two of its own Open Questions being marked "Blocks execution."**
Open Question 1 (does KiCad 10's embedded-symbol importer actually work — H4) and Open Question 2 (is `k = 100/12` applied as exact integer arithmetic without losing the grid guarantee) are both explicitly tagged "**Blocks execution**." Nothing in the Method section enforces that the KiCad spike (its own step 2) happens before, say, step 4 ("Write `SchematicTransform`...") or step 5 (the emitter itself) — a contributor working the checklist top-to-bottom would do the spike first, but nothing structurally prevents starting the emitter with H4 unresolved.
*Recommendation:* Make the checklist itself conditional — e.g. "Steps 3+ MUST NOT start until the H4 checkbox above is checked" — or split the KiCad spike into its own blocking issue so the dependency is enforced by the tracker, not by reading order.

**4. [Medium] The two checks that would actually catch a plausible-but-wrong `.sch` file are unenforced by CI, and the issue already names this failure mode without closing it.**
`.github/workflows/ci.yml:73` installs `iverilog ghdl yosys` for the HDL toolchain but never `lepton-eda`/`lepton-netlist` or `kicad-cli` anywhere in the workflow. So P7 (`LeptonNetlistAcceptanceTest`) will self-skip on every CI run, and H4/the manual KiCad-10 open-and-inspect check (§9: "the only check that the file is actually usable, and no unit test substitutes for it") has no CI presence at all — it is a human procedure a reviewer cannot verify was actually run. §11 of the issue itself warns "a gated oracle that never runs proves nothing... if it skips in every environment the leg is decorative," but offers only "the PR must record whether it ran" as mitigation, which is a self-reported checkbox, not an enforced gate.
*Recommendation:* Either add a best-effort `lepton-eda` install step to CI (mirroring the existing `|| echo "...unavailable..."` pattern at line 73) so P7 has a chance to run somewhere, or explicitly downgrade P7/H4 in the Definition of Done from implied-gating to "permanently manual, tracked by issue comment only."

**5. [Medium] P3/P4's structural acceptance criteria are gameable by a geometrically-empty-but-syntactically-conformant emitter.**
P3 only asserts "each `C ` record is followed by a `[` block that closes with `]`"; P4 only asserts pin numbers are `1..N` with no gaps. Both pass for an emitter that emits a zero-width/zero-height box with pins stacked at the same coordinate — nothing in §5's predictions cross-checks the decoded `B` record's width/height against `Element.getWidth()`/`getHeight()`. The sibling issue #460 (TASK-0089) is more careful about exactly this class of failure — it splits "well-formed" (P4, golden) from "actually functional" (P2, `everyComponentCarriesANonEmptyFootprint`) specifically because "a byte-perfect netlist... would pass a golden comparison and produce nothing on a board." #461 does not apply the same discipline to its own geometry.
*Recommendation:* Add an explicit prediction that decoded `B`-record width/height equal `k·getWidth(e)`/`k·getHeight(e)` for every element, not merely that the block exists.
