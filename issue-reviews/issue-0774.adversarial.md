# Issue #774: TASK-C588-1: the grading-determinism note publishes, with every competitor claim cited to that competitor's own tracker
- Lens: adversarial
- Date: 2026-08-08
- Reviewer: Claude Sonnet 5
- Verdict: needs-rework

## Findings

### 1. [High] AC-1's "reachable from the docs site" presumes infrastructure that does not exist
The issue requires: "`docs/comparisons/grading-determinism.md` exists and is reachable from the docs site." There is no docs site in this repository. `ARCHITECTURE.md`'s own "Recorded decisions" section states plainly: *"Hosted, versioned web documentation is the planned future direction… when it happens, the in-app viewer shrinks to context-sensitive basics pointing at the site"* (ARCHITECTURE.md:252-267) — i.e. it is explicitly **not built yet**. A repo-wide search found no `mkdocs.yml`, no GitHub Pages workflow, no `_config.yml`, nothing matching `docs-site` or `docsite`, and no mention of "docs site" anywhere except that one forward-looking paragraph. Today, `docs/*.md` is "web-readable on GitHub," which is a different and weaker guarantee than "reachable from the docs site" (discoverable navigation, a canonical published URL). TASK-C588-1's Boundary ("Prose and citations") does not include standing up or wiring into a docs site, so AC-1 as literally written cannot be satisfied without either unscoped infrastructure work or silently reinterpreting the criterion down to "committed to the repo and linked from README," which is not what it says.
**Recommendation:** Rewrite AC-1 to match actual infra ("linked from README's Documentation section and from `docs/comparisons/README.md`"), or explicitly scope in whatever minimal docs-site stub is needed, before work starts.

### 2. [High] Required citation "Logisim-Evolution #598" collides with this repo's own issue #598
The required starting citation set includes bare cross-repo issue numbers: "Logisim-Evolution #1546, #598, #950, #1123, #441, #185." I verified live: `anadon/JLS` **already has its own issue #598** — a real, open, unrelated issue ("FEAT-C38-2: every refusal on the way to the board names the fix…", board-export diagnostics). Written in this repo, in prose, "#598" auto-links to `anadon/JLS#598`, not to Logisim-Evolution's #598. Nothing in #774's checklist requires fully-qualified cross-repo URLs, and nothing catches an author who pastes the parent issue's shorthand numbers verbatim into the note. This directly threatens AC-3 ("every competitor claim carries a link to the competitor's tracker") — the failure mode is a note that ships with a citation silently pointing at the wrong project, which is exactly the kind of error the note exists to avoid making about others.
**Recommendation:** Add an explicit AC (or amend AC-3) requiring every competitor citation to be a fully-qualified URL (`github.com/logisim-evolution/logisim-evolution/issues/NNN`, `github.com/CircuitVerse/CircuitVerse/...`), never a bare `#NNN`, and have review check for same-repo auto-links before merge.

### 3. [Medium-High] `ordering_after` blocks a small task on ~15-25mw of unrelated, unshipped work, without justifying the dependency, and is inconsistent with its own parent
`ordering_after: [300, 512]` gates this 0.5-1mw documentation task behind #300 (CAP-06, a 12-20mw grading-verdict capstone, not yet built) and #512 (CAP-28, a 3-6mw performance-publication capstone, also not yet built — its PF-1/PF-2 are still open per the fetched issue body). But the Boundary of #774 itself says: *"No performance number is re-derived here; any that appears cites #512 / #560."* If the note only ever cites #512/#560 rather than needing their output, the hard blocking dependency on #512 shipping is unexplained — the issue being open and citable is already true today. Separately, parent feature #588 lists **three** ordering dependencies for this same deliverable — #300, #512, **and #560** ("the cross-tool harness supplies any performance row a note quotes") — while #774 only carries `[300, 512]`, silently dropping #560. That is an inheritance inconsistency between a task and its declared parent.
**Recommendation:** Either state explicitly why #300's shipped behavior is required for the note's central claim (see Finding 4) and drop the #512 dependency down to "cite, don't wait for," or keep #512 and add #560 for consistency with #588.

### 4. [Medium] Unstated ambiguity about what "grading determinism" claims about JLS itself, and a real tension with this repo's own roadmap doc
The note is framed as a head-to-head where JLS wins on determinism, but the issue never states *which* JLS capability backs that claim. Two readings are both available in-tree and they are not equivalent:
- **(a) "JLS's batch/`-t` interface is byte-reproducible and its grammar/output are a frozen contract"** — true today (`docs/batch-interface.md` §6; README's reproducibility claims), and a fair, checkable claim.
- **(b) "JLS grades deterministically, unlike CircuitVerse's manual grading or Logisim's broken `-test`"** — this reads as a verdict/correctness claim, and `docs/capability-roadmap/lf-04-formal-and-grading.md` (already in this tree) describes JLS's *current* grading story in terms nearly as damning as the competitor bugs this note cites: *"grading is a string diff,"* *"not one of [the `-t` grammar productions] mentions an output,"* *"There is no exit status meaning 'the run completed and the answer was wrong.'"* Reading (b) is not yet true of JLS and only becomes true once #300 ships — which is presumably *why* #300 is an ordering dependency, but #774's body never says so, leaving the actual thesis of the note undetermined and leaving open the risk that a well-meaning author writes reading (b) and overstates a capability JLS doesn't have.
**Recommendation:** State explicitly in the issue which determinism claim is licensed pre-#300 (byte-reproducibility of output) versus what must wait for #300 (a graded verdict), so the note can't accidentally overclaim.

### 5. [Medium] "Tone... a fair" and the depth of the required competitor-advantage admission are unfalsifiable / gameable
"the tone is one their maintainers would recognize as fair" has no operational test anywhere in the issue — no rubric, no second-reviewer requirement, no outreach to the cited projects, not even a banned-adjectives list. AC-5 ("At least one competitor advantage in grading is named plainly") is satisfiable by a token, non-grading-relevant concession (e.g. "Logisim has a nicer toolbar") while still landing every real punch on the topic (grading) the note is about, since the AC doesn't require the named advantage to be *about grading*.
**Recommendation:** Scope AC-5 explicitly to a grading-relevant competitor advantage, and replace the tone requirement with something checkable (e.g., a lint pass for unsourced adjectives about competitor intent/competence, or a requirement that every negative claim be a direct quote from the competitor's own tracker rather than a paraphrase).

### 6. [Medium] The cited evidence base does not exist in this tree
Parent issue #588 says the required citations are "Sourced from `docs/reviews/evidence/2026-08-niche-survey/`" (`logisim-evolution.md`, `circuitverse.md`) in this repo. I confirmed that path does not exist anywhere in the checked-out tree — no `docs/reviews/` directory at all, no file matching `*circuitverse*` or `*logisim*`. #774 inherits the same six-issue citation list with no [verified]/[unverified] tagging (contrast with this repo's own convention in `docs/capability-roadmap/lf-04-formal-and-grading.md`, which tags every external claim). Whoever picks up TASK-C588-1 has no committed primary source to check exact wording or current status of those six numbers against — only bare numbers embedded in issue prose that could be stale by the time the task starts.
**Recommendation:** Commit the evidence files (or point at wherever they actually live) before this task starts, or make "verify each cited issue is still open and still says what's claimed" an explicit first sub-step of AC-3.

### 7. [Low] Word-count ceiling is a soft, gameable proxy for quality
"under ~2500 words" is trivially satisfiable by terse citation-dumping without delivering the "instructor decision aid" substance the Outcome describes, and the "~" makes it unenforceable as stated. Low severity — it's clearly meant as a guardrail against scope creep, not a real content bar, and human review is still the actual gate.

### 8. [Low] "checked against... releases tested" overstates the verification method for a citations-only task
The Boundary confines this task to "Prose and citations," but AC-1 requires "a dated 'checked against' line naming the competitor releases tested" — "tested" implies installing/running Logisim-Evolution and CircuitVerse, which is out of scope here (that's presumably TASK-C588-3's "runnable appendix and freshness gate"). If the actual work is only re-reading trackers/docs, calling it "tested" is itself a small instance of the overclaiming this note exists to police in others.
**Recommendation:** Reword to "release versions reviewed" unless installing and exercising the competitors is actually intended for this task.

## What's solid
- Citing every competitor claim to that competitor's own tracker/docs rather than to JLS's characterization of them is a genuinely good, low-bias documentation practice.
- Requiring at least one named competitor advantage (AC-5, even if underspecified per Finding 5) is a real anti-marketing discipline other projects' comparison pages routinely skip.
- The Boundary section cleanly separates this task from the runnable-appendix/freshness-gate work (TASK-C588-3) and the instructor white paper (#589), avoiding obvious cross-task scope creep.
- "No performance number is re-derived here; any that appears cites #512 / #560" is a sound non-duplication rule, consistent with how other roadmap docs in this repo cite rather than re-measure.
