# Falstad CircuitJS1 (falstad.com/circuit; github.com/pfalstad/circuitjs1)

## FACTS
STACK: Java 8-era source compiled to JavaScript via GWT; runs entirely in-browser on HTML5 canvas. Originally Paul Falstad's 1990s Java applet; Iain Sharp did the GWT port ~2015 (sharpie7/circuitjs1); Falstad's own repo (pfalstad/circuitjs1, created 2016-07-24) is now the active line. LICENSE: GPL-2.0 on both repos (note: GPLv2-only code cannot be relicensed into JLS's GPL-3.0-or-later codebase). SIZE (measured, shallow clone Aug 2026): 248 Java files, 58,562 LoC. Recently refactored: the old CirSim god class is down to 687 lines, split into SimulationManager (1,867 LoC), UIManager (1,560), MouseManager (1,382), Scope (1,474), WireRouter (826). ZERO unit tests (in-tree TestManager.java is a stubbed-out, mostly commented internal scope-golden-data harness, not a suite). ENGINE: Modified Nodal Analysis analog time-domain solver with adjustable timestep; logic gates are analog elements with thresholds, so it is mixed-signal by construction; project's own docs admit "Convergence failed... happens sometimes even with the examples" and "Singular Matrix!" failure modes (falstad.com/circuit/directions.html). RELEASES: continuous; version 4.1.4 bumped 2026-08-02; near-weekly commits by pfalstad through Aug 2026 (github.com/pfalstad/circuitjs1/commits/master) — recent work includes 74LS139 chips, latching relays, wire auto-connect, test-point averaging. COMMUNITY METRICS (GitHub API 2026-08): pfalstad/circuitjs1 = 2,320 stars, 398 forks, 61 open issues, 2,112 commits with pfalstad authoring 1,649 (78%); sharpie7/circuitjs1 = 2,911 stars, 807 forks, 262 open issues, dormant since 2024-01-22. Combined ~5.2k stars / ~1,200 forks, plus an uncountable non-GitHub user base (the web app is the default embedded sim in physics/EE courses worldwide, e.g. physicslabs.ucd.ie/documentation/Falstad_circuit_sim, physics.wisc.edu lab handouts). INSTALL: zero — it is a URL (falstad.com/circuit, mirror lushprojects.com/circuitjs); community offline builds: Electron packaging files in-repo, SEVA77 "CircuitJS1 Desktop Mod" NW.js builds for Win/Linux/macOS incl. arm64 (github.com/SEVA77/circuitjs1), FOSSEE forks (github.com/frg-fossee/circuitjs-pfalstad) for India's eSim ecosystem. DOCS: directions.html + hundreds of built-in example circuits in the Circuits menu; circuits serialize to a compact text format embeddable in a URL ("Export as Link") and iframe-embeddable with startCircuit=/ctz= parameters; documented JavaScript control API for embedding pages (falstad.com/circuit/doc/js-interface.html) used by e.g. the AVR8js co-simulation demo (falstad.com/circuit/avr8js/logic.html). Build modernized: Gradle + Docker/Podman + Gitpod/Codespaces alongside legacy Eclipse GWT plugin; CONTRIBUTING.md present.

## SCORES
- onramp_install: 5 — Zero-install web app: falstad.com/circuit loads a running, animated circuit in seconds on any device; this is the category ceiling.
- onramp_learning: 5 — Opens with a live animated LRC circuit (yellow current dots, voltage color gradients), hover shows component readouts, hundreds of built-in examples, and any circuit shares as a URL — first circuit in under a minute.
- tech_sim_semantics: 2 — Analog MNA with thresholds, not a digital timing model: no per-gate propagation-delay rigor, no X per-bit, race/hazard behavior is emergent and unreliable (ring counter 'unpredictable behaviour' pfalstad#364; documented 'Convergence failed'/'Singular Matrix' errors) — though real HiZ and true mixed-signal are things JLS cannot do.
- tech_scale_perf: 2 — Matrix-solve engine bogs down on large circuits — single-threaded (sharpie7#228), resource-usage and UI-lag complaints (sharpie7#41, #613); nothing near Digital's 120 kHz-CPU class for big digital designs.
- tech_hierarchy_reuse: 2 — Subcircuits (custom composite models) exist but are fragile — creation silently fails (sharpie7#400), labeled nodes truncated to one pin (pfalstad#134) — no parameterization, no cross-file libraries, no buses.
- tech_testing_grading: 1 — No test vectors, no batch/CLI mode, no autograde ecosystem; the in-tree TestManager is stubbed out; grading a Falstad circuit means eyeballing it.
- tech_hdl_interop: 1 — No Verilog/VHDL export or import, no netlist interchange (its text format is proprietary), no FPGA path.
- extensibility: 3 — Documented JS embedding/control API (doc/js-interface.html) enables scripted labs and co-simulation (AVR8js demo), plus in-app Custom Logic and composite models; but new native components require forking the GWT Java build.
- code_elegance: 2 — GWT (a fading toolchain) compiling Java-8-style code, zero automated tests, no CI quality gates; credit for the recent god-class breakup (CirSim 687 LoC now, split into managers) and Gradle/Docker build modernization.
- contributor_experience: 3 — CONTRIBUTING.md, Gitpod/Codespaces/Docker onboarding, and a famously responsive maintainer who closes bugs within days (pfalstad#364/#365 marked completed in June 2026), but no roadmap, no good-first-issues, and 78% of commits are one man.
- community_size: 5 — ~5.2k combined stars and ~1,200 forks across the two repos, but the real number is the web: it is the default embedded simulator in university physics/EE course pages worldwide — the largest user base of any tool in this survey.
- momentum: 4 — Near-weekly commits and version bumps through Aug 2026 (v4.1.4) after a decade of continuity; docked one point because it is bus-factor-1 with no roadmap and the historical community repo (sharpie7) is dead since Jan 2024.

## TOP USER COMPLAINTS
- Subcircuit/hierarchy fragility: creating a subcircuit silently does nothing (sharpie7#400) and shared labeled nodes get truncated to one pin (pfalstad#134); users trying to build counters from flip-flop blocks hit this wall repeatedly — the single biggest digital-side pain.
- Performance/lag on non-trivial circuits: 'Javascript version has started to use much more resources' (sharpie7#41), request to pause sim during UI interaction to reduce lag (sharpie7#613), request for multithreading closed as infeasible (pfalstad#228).
- Inscrutable solver errors for students: 'Convergence failed' (pfalstad#124) and 'Singular Matrix!' with docs conceding these happen 'even with the examples' — a beginner-facing tool whose failure messages require expert knowledge.
- Unreliable sequential-logic behavior: ring counters behave unpredictably (pfalstad#364); community consensus that 'for complicated digital ICs Falstad isn't practical' — analog solving of digital circuits produces non-deterministic-feeling races.
- No first-party offline/desktop version: recurring requests (sharpie7#121, #393) answered only by third-party NW.js/Electron forks (SEVA77 Desktop Mod), fragmenting the install story.
- Sharing/export breakage and data-loss anxiety: TinyURL link creation broken plus other export bugs (sharpie7#349); no cloud save; requests to persist options in local storage (pfalstad#369); printing broken (pfalstad#365).
- Dated, modal drawing UX: wire-drawing and selection quirks (wire auto-connect only fixed July 2026), wrong segment highlighted in 'wire loop detected' (pfalstad#323), no wire color customization (pfalstad#44).
- Component-model accuracy gripes from the analog crowd: MOSFET missing parasitic diode (sharpie7#243), inductor current errors (sharpie7#146, pfalstad#376) — reminders that its models are pedagogical, not SPICE-grade.

## DEV COMMUNITY
Bus-factor 1 with a halo of drive-by contributors. Paul Falstad authored 1,649 of 2,112 commits (78%); the GWT port author (sharpie7, 202 commits) exited years ago and his repo — still the more-starred one at 2,911 stars — has been dead since Jan 2024, stranding 262 open issues and splitting the community's issue history across two trackers. Recurring outside contributors are few and small: esaruoho (85), nulldg (43), SEVA77 (37), Mervill (22); most others are 1-3 commit translation or single-component patches. WHAT ATTRACTS: contributing to a beloved, universally known tool; a legendary, fast-responding maintainer; a flat per-component architecture (one Elm subclass per part) that makes 'add a component' a tractable first PR; recently modernized onboarding (Gradle, Docker, Gitpod/Codespaces). WHAT REPELS: GWT is a dying toolchain that young web devs won't touch and Java devs find alien; zero automated tests means every PR risks silent regression and review burden falls entirely on Falstad; no roadmap, no good-first-issue curation; GPL-2.0; and the knowledge that architectural decisions are one man's taste — the project is Falstad's instrument, not a community platform. Net: an enormous USER community feeding a tiny, gated DEV community — the fork ecosystem (807+398 forks, offline mods, FOSSEE) is where surplus contributor energy actually goes.

## SWITCH ANALYSIS
### pull_users
The winnable Falstad users are the ones misusing it: digital-logic instructors and students who stretch an analog solver into sequential-logic territory and hit unpredictable ring counters (#364), broken subcircuits (#400/#134), convergence errors, and zero grading. JLS's concrete pull for exactly that slice: delay-accurate deterministic discrete-event simulation (races become explainable, not mysterious), working hierarchy via subcircuits, batch grading with -t vectors + VCD + documented stability contract (nothing remotely comparable exists in Falstad-world), and Verilog/VHDL export as the bridge to real EE curricula. Migration cost is real but boundable: Falstad's circuit text format is compact and documented-by-source, so a JLS importer for its logic-element subset (gates, FFs, counters, logic inputs/outputs, labeled nodes) is maybe a two-week project and would convert a decade of course materials; the unboundable cost is that Falstad users start from a URL and JLS starts from an installer.
### pull_devs
Contributors repelled by Falstad-world's zero-test GWT codebase, single-gatekeeper review, and the abandoned sharpie7 repo with 262 orphaned issues. JLS's pitch: modern Gradle/Nix build, mutation testing, NullAway, warnings-as-errors, 240 test files — a codebase where your PR can't silently break the sim. Honest counter: Falstad just executed the refactor JLS still owes itself (CirSim is now 687 lines; SimpleEditor is 5,852), and devs contribute where users are — 3 stars attracts no one. The realistic dev pull is not defection but recruitment of the fork-ecosystem energy (offline packagers, FOSSEE integrators) who want a maintained, installable, scriptable educational sim with a real test culture.
### jls_deficits
Brutal list: (1) No web version — Falstad's entire moat is 'it's a URL'; every lecturer embed, every share link, every Chromebook student is unreachable by a Swing app, full stop. (2) No analog, at all — Falstad's core identity (RLC, transistors, op-amps, 555s, animated current intuition) has no JLS counterpart until the deferred analog capstones ship, and even then JLS would be attacking the entrenched category king on its home turf. (3) No animated current/voltage visualization — the single feature HN and physics departments name as why it teaches intuition. (4) No live scope/chronogram — Falstad has excellent real-time scopes with FFT; JLS's chronogram panel doesn't exist yet. (5) No share-a-circuit-as-URL and no hundreds-of-examples menu. (6) Anonymity: 3 stars and no README screenshots versus a household name embedded in course pages worldwide. (7) True mixed-signal and real HiZ analog interactions are things Falstad does natively and JLS's 2-state domain cannot.
### winnable_verdict
The analog/intuition core — the reason every lecturer embeds it — is NOT winnable and should not be contested; a Swing app will never beat a URL with dancing electrons for physics intuition. The winnable segment is the digital-coursework overflow: courses that outgrow Falstad's gates the moment they need deterministic timing, hierarchy that works, autograding, or an HDL on-ramp. Minimum bar to convert them: (1) a Falstad-text importer for the logic subset so existing course circuits carry over; (2) a chronogram panel, because Falstad users are trained on live waveforms; (3) a zero-ish-install path (web build via CheerpJ/WASM, or at minimum a one-click signed launch plus shareable circuit files/links); (4) README screenshots and a 'from Falstad' migration page. Absent (1)-(3), expect zero migration regardless of technical superiority — the on-ramp asymmetry dominates. The dev-side minimum bar is smaller: finish the SimpleEditor decomposition so JLS's 'elegance' pitch survives first contact with the repo, then recruit from the orphaned sharpie7 issue tracker and offline-fork community.
