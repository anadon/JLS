# Digital (hneemann) — github.com/hneemann/Digital

## FACTS
STACK: Java 8 (pom targets 1.8), Swing, Maven; zero runtime deps beyond JRE. LICENSE: GPL-3.0. SIZE (measured from clone, 2026-08): 101,191 LoC main Java across 840 files + 24,457 LoC test Java across 245 files; 4,566 commits since first commit 2016-03-11; largest file CircuitComponent.java 2,957 lines (no JLS-style god class). QUALITY GATES: Checkstyle with mandatory Javadoc (88 modules, sun_checks_neemann.xml), PMD, FindBugs (not SpotBugs), JaCoCo; zero TODO comments in 101k LoC; CI is bitbucket-pipelines.yml, NOT GitHub Actions (fork PRs get no visible CI). RELEASES: v0.31 Sep 3 2024 (latest — 23 months stale), v0.30 Feb 2024, v0.29 Feb 2023, ~1-2/yr historically (https://github.com/hneemann/Digital/releases); commits continue through June 2026 but velocity collapsed: 330 (2021) → 82 → 49 → 32 → 15 (2025) → 3 (2026 YTD). INSTALL: download Digital.zip, unzip, run shell script (Linux) or Digital.exe/jar (Win/mac); requires separately installed JRE 8+ (README points Windows users to Temurin) — no signed installers, no package managers, no web version. COMMUNITY: 5.9k stars, 586 forks, 170 open issues, 26 open PRs / 118 closed ever (https://github.com/hneemann/Digital). DOCS: multi-language generated manual (en/de/es/it/pt/zh sources in src/test/resources/docu), docu-tests verify docs match components, 727 example .dig files nearly all with embedded test cases, 3 screenshots in README. FEATURES (README, his own Logisim-comparison essay): event-based simulator with documented two-phase read/write micro-step (Node.java Javadoc), random-order settling to surface races, oscillation detection + single-gate-step root-causing, per-bit HiZ (ObservableValue keeps value+highZ long masks — but no X state), 120 kHz simulated processor clock on an i5-3230M, ~2,400-component Conway's Life "works just fine", Quine-McCluskey truth-table synthesis, FSM editor, parameterized generic circuits (hgs template/script engine), 74xx library, VHDL+Verilog export, iverilog/GHDL co-simulation (core/extern), FPGA board flows (BASYS3, TinyFPGA BX; toolchain/Configuration.java templates for vendor tools), GAL/ATF JEDEC export, TCP remote-control API for assembler IDEs, custom Java components via jar (https://github.com/hneemann/digitalCustomComponents). CLI (cli package, v0.31): test / run / svg / stats subcommands — batch grading is real (CommandLineTester.java). COURSE USE: Western Michigan Univ ECE 2500, 18 exercises, 8 semesters, zyBooks self-grading integration (https://github.com/hneemann/Digital/discussions/1266).

## DEV COMMUNITY
Pure single-maintainer autocracy in maintenance-mode decline. Helmut Neemann (a German professor) wrote it clean-room from 2016 and authored 97.7% of all 4,566 commits; 38 lifetime authors, but the #2-#4 'contributors' are his own alternate accounts. Last 12 months: 28 commits, 25 by him, 3 one-commit drive-bys (typo/translation-level). WHAT ATTRACTS: pristine, fully-Javadoc'd codebase (zero TODOs, enforced style, strong test suite incl. docu-tests), trivially buildable with plain Maven+JDK8, huge visible user base to serve. WHAT REPELS: (1) the maintainer explicitly channels contributions away from PRs (CONTRIBUTING.md: if you can't run mvn verify, 'it is easier for me if you don't create a pull request'); (2) feature PRs die — 26 open, and ambitious ones (new UI #1464, keybind settings #1470) were closed unmerged in late 2025; (3) CI lives on Bitbucket, so GitHub fork PRs get no automated feedback; (4) Java-8/Swing stack with mandatory-Javadoc checkstyle is a high, old-fashioned bar; (5) every decision waits on one man whose commit rate has fallen 95% since 2021, with no co-maintainer, no org, no succession plan — classic unaddressed bus-factor-of-1 on a 5.9k-star project. Result: thousands of users, effectively zero empowered developers, and a growing pool of rebuffed would-be contributors.

## SWITCH ANALYSIS
### pull_users
The levers JLS already holds: signed zero-JDK installers on all OSes (Digital makes students install a JRE first), an actively-released project (Digital: no release in 23 months), and modern packaging (Nix/container). The levers JLS could build cheaply from Digital's own ignored backlog: dark mode/theming (#693/#1387/#1477), live dive-into-subcircuit (#84, open 8 years), wire coloring (#1308), a searchable name. But migration cost is the killer: courses are anchored to .dig files, 727 tested examples, zyBooks labs, and Digital's manual — no one moves without a high-fidelity .dig importer (format is plain XStream XML — importable with bounded effort) plus test-vector conversion so instructors' grading suites keep working. Without feature parity on parameterized generics, FSM editor, and truth-table synthesis, an importer alone converts nobody.
### pull_devs
This is the soft target. Digital has a queue of demonstrably motivated, demonstrably rejected contributors (authors of #1464 new-UI and #1470 keybindings PRs, plus 26 open PRs). JLS can offer exactly what Digital structurally cannot: fast PR turnaround, GitHub-native CI visible on forks, a stated plugin/extension API instead of an unstable internal Java API, and a maintainer who wants co-maintainers. Concretely: triage Digital's open PR list, invite those authors, and implement their rejected features in JLS as headline items. JLS's stricter gates (mutation testing, NullAway) are a credible quality story to Digital-calibre devs — but only if CONTRIBUTING makes the bar feel automated-and-fair rather than gatekept.
### jls_deficits
Brutal list of what blocks any pull today: (1) no subcircuit parameterization vs Digital's generics — instructors use these; (2) no truth-table/Quine-McCluskey synthesis and no FSM editor — core coursework features; (3) no chronogram panel vs Digital's measurement graphs; (4) JLS is 2-state+HiZ at signal level while Digital carries per-bit HiZ masks on buses; (5) no FPGA/board path at all vs BASYS3/TinyFPGA + vendor toolchain templates; (6) no co-simulation (iverilog/GHDL) behind JLS's Verilog/VHDL export; (7) no published performance numbers vs Digital's 120 kHz/2,400-component receipts — JLS must benchmark or concede; (8) 3 stars and no screenshots in the README vs 5.9k stars, 727 examples, and a six-language generated manual — JLS's HTML 3.2 help viewer is embarrassing next to Digital's docs pipeline; (9) SimpleEditor at 5,852 lines is worse than anything in Digital's codebase (max 2,957, zero TODOs) — Digital wins the code-elegance comparison today despite its Java-8 stack.
### winnable_verdict
Users: NOT winnable head-on in the near term — Digital is technically superior on 6 of 8 tech dimensions and course-locked. Contributors: WINNABLE NOW — the rejected-PR pool and bus-factor anxiety are real, and JLS's modern gates + welcoming merges is a genuine differentiator; minimum bar: public plugin API, <1-week PR turnaround demonstrated, kill the god class so the codebase inspection doesn't lose to Digital's. Instructors (the user segment that moves whole cohorts): winnable on a 1-2 year horizon IF Digital's stall becomes a visible risk; minimum bar to be the credible successor: (a) .dig importer with test-vector translation, (b) parameterization + FSM + synthesis parity, (c) benchmark within ~2x of Digital's 120 kHz with published methodology, (d) screenshots, worked examples, and a real manual. The strategic play is explicitly to position JLS as the maintained, modern successor before someone forks Digital and claims that role first.
