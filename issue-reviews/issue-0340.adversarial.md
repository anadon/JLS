## Findings, most severe first

**1. The feature's own Global Invariant 6 is already violated by its own filed child task.** §4 states: *"6. **The digest is derived, never stored.** No child may cache it into the saved bytes."* But TASK-0039 is filed as **#417**, and #417 §7.1 specifies, verbatim: `SubCircuit` blocks gain two `String` attributes before the nested `CIRCUIT` block: `String defid "vendor:library:name:version"` and `String defdigest "<64 hex characters>"` — i.e. the digest *is* written into the saved bytes, unconditionally, on every save. #417 rationalizes this by always recomputing on load and treating the stored value as an untrusted claim (§7.11: *"the recomputed value wins and the mismatch is reported"*) — a reasonable design — but that is not what Invariant 6 says. Invariant 6 forbids caching the digest into saved bytes at all, full stop, and gives a reason (*"storing it would let a stale digest outlive the definition it names"*) that #417's design doesn't actually solve, it works around. Either #340's invariant is wrong and needs restating to allow "stored-but-always-recomputed-and-untrusted," or #417's interface contract needs to drop `defdigest` from the wire format (e.g. compute-on-demand only, never persisted). As written, an implementer following #417 to the letter fails #340's own Definition-of-Done item *"§4 (Global Invariants) hold at the final commit, re-verified"* by construction. This is not a hypothetical drift — the contradiction exists between two documents that are both currently open and both currently "correct" per their own internal logic. **Recommendation:** resolve this before either issue proceeds — restate Invariant 6 to describe the store-and-revalidate discipline #417 actually implements, or strip persisted `defdigest` from #417's file-format change.

**3. The reference-resolution policy asymmetry (Open Question 5) creates a gameable safety hole.** The recommended defaults are: digest-mismatch on a reference resolved *through a library container* → **refuse**; digest-mismatch on a reference resolved *directly against a file the parent declared* → **accept-and-report**. Both paths produce the *same observable object* — a `SubCircuit` instance nested by reference — and per criterion 7/§3 a plain `.jls` file and a library container are explicitly two resolution sources for the same reference mechanism. That means the actual on-disk safety guarantee ("this collision policy is enforced") is only as strong as its weakest path: anyone who wants a definition to silently drift across instances without a load refusal simply avoids packaging it as a library and references the bare `.jls` file instead, which is the softer, accept-and-report branch. IC-3 ("a collision is loud and names both sides") is written and evidenced only against the library/TASK-0039 collision predicate, not against this file-reference path — so IC-3 could pass in full while the exact failure mode it exists to prevent (a silently-diverged shared definition) remains reachable via criterion 7's own file-reference feature. **Recommendation:** either make both paths refuse by default (require an explicit user action — e.g. "accept the new digest" — to convert an implicit accept-and-report into an update, rather than making acceptance the silent default for one path), or add an integration criterion that specifically exercises the file-reference accept-and-report path and shows it does not defeat the collision guarantee the container path provides.

Cost is scoped to this issue only; the reachable total on the critical path is not stated anywhere a reader can avoid computing by hand.** §Cost prices FEAT-016 alone at 6–11 mw (7–11 mw under the stricter test). But FEAT-016 is `blocked_by: [319]`, and #319 is itself banded at 4–7 mw with its own three unfiled/filed sub-tasks; #319 in turn is `blocked_by: [334]` → `[315]`. Downstream, FEAT-016 `blocks: [357]`, and #357 is banded 25–36 mw specifically because its 4 wk of named task rows don't cover its 25-call-site migration residual — a gap #357 itself calls "the largest such gap in the plan." None of this is arithmetic error inside #340 (each issue's own band-vs-row-sum reconciliation is shown and checks out), but a reader who wants to know "what does it cost to make 'nest systems' actually usable end-to-end" has to chase four issues and sum bands nobody sums for them, and the total lands well past 40 maintainer-weeks for a project ARCHITECTURE.md describes as a "single-maintainer pedagogy tool." **Recommendation:** state the reachable critical-path total (or a pointer to where it's computed) in this issue's Cost section, since the issue's own text already invokes #319 and #357 by number for ordering — reusing them for a rolled-up cost is a small addition with real value for anyone deciding whether to fund this.

**5. Invariant 7's acyclicity test coverage is narrower than the invariant.** IC-8(c) tests only a direct two-file mutual import (`a.jls` ↔ `b.jls`). Invariant 7 claims the general property ("an import graph over files is acyclic"), which needs a transitive case (`a→b→c→a`) to actually pin cycle detection as graph-based rather than a special-cased direct-back-reference check — a implementation that only checks "does the file I'm about to load import the file I came from" would pass IC-8(c) and still infinite-loop or silently mis-resolve on a three-file cycle. **Recommendation:** add a transitive-cycle case to IC-8 before this criterion is considered demonstrated.
